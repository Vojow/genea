# Contributing

Use minimal synthetic examples when reporting a problem or proposing a change. Do not include real family records, names, contact details, personal correspondence, database dumps, browser sessions, credentials or private screenshots in issues, logs or fixtures.

Before a code change, describe its intended behavior and the test that will distinguish success from failure. Run the relevant unit tests against a temporary workspace. Add or update a source/review contract when the behavior affects uncertainty, identity, privacy or provenance.

Backend and frontend changes should have bounded ownership and an independent review for privacy-sensitive work. Preserve changes made by others. Generated data and operational backups are local artifacts and do not belong in source control.

The maintainer may narrow contribution scope while this experimental candidate is prepared. Contributions to the project are made under the MIT license in LICENSE. Third-party additions must preserve their original license and attribution requirements.
